# Code Coverage Report & Improvement Plan
**Date:** 2026.01.01
**Project:** mdsol (Solitaire)

## 1. Executive Summary
The `mdsol` project currently has decent coverage for the `engine` (Game Rules) and `solver` (Search Algorithm) modules (15 tests passing).
However, significant portions of the application logic reside in `src/main.rs` (UI Layout, Hit Testing, Animation Physics) and `xtask/src/main.rs` (Asset Pipeline), which are currently untested.

**Goal:** Increase coverage to 98% by adding unit tests for pure functions in `main.rs` and helper functions in `xtask`.

## 2. Gap Analysis

### `src/main.rs` (UI Logic)
This file is the Win32 entry point, but it contains substantial pure logic that should be tested:
*   **Geometry:** `point_in_rect` (Trivial but foundational).
*   **Layout:** `CardMetrics::compute` calculates card sizes and positions based on window size. This is critical for responsiveness.
*   **Interaction:** `hit_test` determines what the user clicked on (Stock, Waste, Tableau, Foundation). This involves complex bounding box logic.
*   **Animation Physics:** `integrate_victory_cards` (Gravity, bouncing) and `emit_victory_card` (Trajectories). These are pure math functions.
*   **Utilities:** `lparam_point`, `make_int_resource` (though `make_int_resource` is `const`).

### `xtask/src/main.rs` (Build Tools)
Contains logic for asset processing:
*   **String Manipulation:** `capitalize`, `normalize_path_for_rc`.
*   **File Finding:** `find_svg_for`, `find_png_for` (Can be tested with mock file systems or temp dirs).
*   **Image Processing:** `downsample_pixmap` (math heavy).

## 3. Improvement Plan

### Stage 1: Main UI Logic (High Value)
**Objective:** Cover layout, interaction, and animation logic in `src/main.rs`.
1.  **Layout Tests:**
    *   Test `CardMetrics::compute` with various window sizes (small, large, aspect ratios) to ensure card sizes and margins are reasonable.
2.  **Interaction Tests:**
    *   Test `hit_test` with a constructed `WindowState`.
    *   Verify hitting Stock, Waste, and specific Tableau cards (top, middle, bottom).
    *   Verify `None` for clicks in margins/gaps.
3.  **Animation Tests:**
    *   Test `integrate_victory_cards` to verify gravity acceleration and bouncing (y-velocity reversal).

### Stage 2: Helper Functions
**Objective:** Cover utility functions in `main.rs` and `xtask`.
1.  **Main Utils:** Test `point_in_rect`.
2.  **Xtask Utils:** Test `capitalize` and `normalize_path_for_rc`.

## 4. Execution Strategy
I will start with **Stage 1** by adding a `#[cfg(test)] mod tests` block to `src/main.rs` (conditionally compiled so it doesn't interfere with the Win32 binary). I will need to be careful about `WindowState` initialization to avoid GDI calls (which should be safe as `Option<BackBuffer>` defaults to `None`).
