## Overview

The Solitaire application implements a sophisticated dual-mode victory animation system with smooth physics-based animations, hint highlighting, and pointer speed tracking.

## Key Components

### Animation Structures

AnimCard (Lines 1947-1956) - Used by Modern mode for physics-based bouncing
ModernVictoryAnimation (Lines 1958-1971) - Fixed timestep, pointer speed influence (1.0x to 4.5x)
ClassicEmitter (Lines 1979-1988) - Constant horizontal velocity, simpler gravity
ClassicVictoryAnimation (Lines 1990-2104) - Off-screen layer buffer for trails

### Animation Constants

Modern Mode (Lines 130-139):
- ANIM_EMIT_INTERVAL: 0.16s
- ANIM_FIXED_DT: 0.02s (20ms timestep)
- ANIM_GRAVITY: 3000.0 px/s^2
- ANIM_FLOOR_DAMPING: 0.78, ANIM_WALL_DAMPING: 0.82
- ANIM_EXIT_BOUNCES: 8

Classic Mode (Lines 140-150):
- CLASSIC_STAGGER: 0.2s, CLASSIC_GRAVITY_STEP: 3.0 px/frame
- CLASSIC_BOUNCE: 0.7, CLASSIC_SPEED_SCALE: 4.0x

### Victory Animation System (Lines 2141-2210)

Initialization:
1. Check if animation running
2. Gather all cards from game state (foundations, waste, stock, tableau, drag)
3. Filter to foundation cards only (unless forced)
4. Order by rank (King to Ace, all suits before next rank)
5. Create Modern or Classic animation
6. Start 16ms timer for 60 FPS updates

### Animation Update Loop

Modern Update (Lines 2481-2526):
- Delta time with safeguards
- Speed scale from pointer movement
- Emit cards every 160ms
- Fixed timestep physics integration
- Check completion

Classic Update (Lines 2527-2576):
- 4.0x speed scale (no pointer influence)
- Emit one card when all previous finished (200ms stagger)
- Fixed timestep physics
- Flush to layer buffer

### Physics Calculations

Modern Mode:
- emit_victory_card (Lines 2587-2614): Horizontal 760-950 px/s, Vertical -1050 to -1150 px/s
- integrate_victory_cards (Lines 2616-2664): Gravity 3000 px/s^2, Wall bounce 82%, Floor bounce 78%, Settles after 8 bounces

Classic Mode:
- emit_classic_card (Lines 2408-2424): Random horizontal 5-15 px/frame
- integrate_classic_emitters (Lines 2426-2468): Gravity +3.0 px/frame, Bounce 0.7, Constant horizontal

### Rendering System (Lines 3439-3646)

Modern: Direct card rendering at current positions (fast)
Classic: Alpha-blend layer buffer + current emitters (authentic XP effect)

Foundation Hiding (Lines 3498-3514): Emitted cards disappear from foundations

BackBuffer Layer (Lines 1305-1394): 32-bit RGBA DIB section for Classic mode

### Hint Highlighting

Fields (Lines 538-540): hint_highlight, hint_highlight_ticks (2 = 200ms), hint_highlight_enabled

Application (Lines 3718-3890) - Priority system:
1. Tableau to Foundation (reveals hidden)
2. Tableau to Tableau (reveals hidden)
3. Waste to Foundation
4. Tableau to Foundation (any)
5. Waste to Tableau
6. Tableau to Tableau (any)

Rendering (Lines 3612-3634): Golden yellow rgb(255,210,0), rounded rectangle, 3px thickness, 200ms duration

### Pointer Speed Tracking

Tracking (Lines 801-813): distance/time, clamped to 4000 px/s, exponential moving average (alpha=0.2)
Application (Lines 2491-2494): Base 1.0x + pointer_speed * 0.0015, max 4.5x total
Decay (Line 2579): 10% per frame

### Animation Lifecycle

1. Victory Detection (Lines 2666-2674) after card draws, drags, undo/redo
2. Start (Lines 2141-2210): gather, filter, order, create, start timer
3. Update Loop: 16ms timer, delta time, emit, integrate
4. Rendering: Every WM_PAINT
5. End (Lines 2131-2139): kill timer, drop animation, destroy layer
6. Manual Cancel: Escape, New game, Undo/Redo, menu

### Technical Details

Fixed Timestep Physics: Both modes use accumulator pattern

Memory Management:
- Modern: Low overhead, no layer buffer
- Classic: Layer buffer (e.g., 8.3 MB for 1920x1080)

Performance:
- Modern: Faster, direct rendering
- Classic: Slower, full-screen alpha blending

## Summary

Two distinct animation styles:
- Modern: Interactive, pointer-influenced bouncing physics
- Classic: Authentic XP cascade with layer-based trails
- Fixed timestep physics for frame-rate independence
- Hint system with golden outline and priority-based selection
- Robust lifecycle management with proper resource cleanup
