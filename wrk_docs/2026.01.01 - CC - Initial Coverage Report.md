## 2. Detailed Analysis

### `src/engine.rs` (Critical Priority)
This file contains the `GameState` struct and all move validation logic.
- **Untested Public Methods:**
    - `deal_new_game`, `deal_again`: Needs verification of card distribution and state reset.
    - `stock_click`: Needs to test drawing (1 vs 3) and recycling.
    - `move_waste_to_foundation`, `move_waste_to_tableau`: Needs validity checks.
    - `move_tableau_to_foundation`: Needs rule checks.
    - `extract_tableau_stack`, `place_tableau_stack`: Complex logic for moving multiple cards.
    - `force_complete_foundations`: Auto-win logic.
    - `is_won`.
- **Untested Private Helpers:**
    - `is_valid_tableau_run`, `can_place_on_tableau`, `can_place_on_foundation`.

### `src/solver.rs` (High Priority)
- **Current Tests:** `test_safe_to_foundation_basics`, `test_kplus_indices`, `test_solve_trivial`.
- **Missing Coverage:**
    - `generate_moves`: Needs to be tested with specific setups to ensure it finds all legal moves (tableau-to-tableau, waste usage, etc.).
    - `apply_move`: Verify state mutation correctness.
    - `State::normalize`: Critical optimization logic, needs to be verified to not break valid states.
    - `dfs`: Edge cases (timeout, depth limits).

### `src/main.rs` (Low Priority for Auto-Tests)
- mostly mostly boilerplate Win32 event handling.
- **Recommendation:** Keep manual testing for UI. Ensure `wndproc` delegates complex logic to `engine.rs` (which it largely does).
