# Dialogs and Settings Persistence

**Date:** 2025.11.06
**File Analyzed:** src\main.rs
**Purpose:** Document the dialog system implementation and registry-based settings persistence

## Overview

The Solitaire application implements three modal dialogs (Options, About, Help) and a comprehensive registry-based settings persistence system.

Registry Base Key: Software\0x4D44 Software\Solitaire under HKEY_CURRENT_USER

## Dialog System Summary

### 1. Options Dialog (IDD_OPTIONS)

- Resource ID: 402
- Procedure: options_dialog_proc (lines 3931-4030)
- Function: show_options_dialog (lines 3891-3902)
- Controls: 9 checkboxes/radios for game settings
- On WM_INITDIALOG: Loads current settings into controls
- On WM_COMMAND IDOK: Reads controls, updates state, persists to registry, syncs with game engine

### 2. About Dialog (IDD_ABOUT)

- Resource ID: 401
- Procedure: about_dialog_proc (lines 4065-4234)
- Function: show_about_dialog (lines 3648-3659)
- Custom GDI state: AboutDialogState with brushes and pen
- WM_PAINT: Draws 4 playing cards, version info, copyright, license text
- Resource cleanup in WM_COMMAND and WM_DESTROY

### 3. Help Dialog (IDD_HELP)

- Resource ID: 403
- Procedure: help_dialog_proc (lines 3674-3716)
- Function: show_help_dialog (lines 3661-3672)
- WM_PAINT: Renders 6 keyboard shortcuts as text
- Simple dialog with no custom state

## Registry Persistence

All functions use consistent pattern: open key, query/set value, close key, validate, return Option or default.

### Registry Values

Base: HKEY_CURRENT_USER\Software\0x4D44 Software\Solitaire

1. WindowBounds (20 bytes): [left, top, width, height, maximized] - Lines 183-296
2. DrawThree (4 bytes): 0=DrawOne, 1=DrawThree - Lines 1436-1494
3. ScoringMode (4 bytes): 0=Standard, 1=Vegas - Lines 1496-1551
4. Timed (4 bytes): 0/1 - Lines 1553-1627 (with VegasCumulative)
5. VegasCumulative (4 bytes): 0/1 - Lines 1553-1627
6. HintHighlight (4 bytes): 0/1 - Lines 1629-1682
7. VictoryStyle (4 bytes): 0=Classic, 1=Modern - Lines 1684-1738
8. VegasBank (4 bytes signed): Bank balance - Lines 1740-1791

All use REG_BINARY with little-endian encoding.

### Persistence Points

Load: WM_CREATE (lines 636-651)
Save: WM_DESTROY (line 1183), Options dialog OK, specific events (Vegas bank)

## Dialog-Game Synchronization

WindowState (lines 506-542) holds all settings. Options dialog:
1. Opens: Reads WindowState via get_state(GetParent(hwnd))
2. User edits: Changes tracked in dialog only
3. OK: Reads all controls, updates WindowState, updates menus, persists registry, syncs GameState
4. Cancel: No changes

Example (lines 3963-3971):
```rust
if state.game.draw_mode != new_mode {
    state.game.draw_mode = new_mode;       // Update engine
    update_draw_menu(owner, new_mode);     // Update menu
    update_status_bar(state);              // Update UI
    save_draw_mode(new_mode);              // Persist
}
```

Timer management tied to timed_scoring: stop/start timer, handle pause on minimize, resume on restore.

## Error Handling

Registry: Silent failure pattern - errors ignored, defaults used. No error logging.

Dialogs:
- About: If GDI creation fails, cleanup and return 0 (fallback rendering)
- Options/Help: Silent return if controls not found

Rationale: Settings non-critical, app runs fine with defaults, avoids error dialogs.

## Key Observations

Strengths:
- Consistent registry pattern across all settings
- Clear separation: Dialogs (UI) vs WindowState (app) vs GameState (engine)
- Atomic operations: All changes on OK, none on Cancel
- Defensive validation and resource cleanup

Considerations:
- REG_BINARY vs REG_DWORD (all use REG_BINARY for consistency)
- Silent failures (no logging for debugging)
- Vegas bank resets if cumulative toggled off then on
