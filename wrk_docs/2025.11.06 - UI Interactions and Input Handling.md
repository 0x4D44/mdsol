## Executive Summary

The Solitaire UI implements a sophisticated two-phase interaction system:
- **Click vs Drag:** 4-pixel threshold disambiguates intention
- **Drag-Drop:** Full validation, undo support, visual feedback, mouse capture
- **Two-Click Selection:** Alternative input method for precision/accessibility
- **Hit Testing:** Optimized algorithm with overlapped card support and caching
- **Keyboard:** Windows accelerator-based shortcuts (Ctrl+Z, H for hint, etc.)
- **Focus:** Validated focus management for keyboard navigation
- **Double-Click:** Auto-move to foundations

All input routes through main window procedure (wndproc, line 581).

## 1. Core Data Structures

### HitTarget (Lines 1909-1918)
Unified clickable region representation:
- Stock, Waste, Foundation(usize), Tableau{column, card_index}, None
- Used for hit testing, focus, event routing, visual feedback

### DragContext (Lines 1926-1933)
Active drag operation state:
- source: DragSource (Waste or Tableau{column})
- cards: Vec<Card> being dragged
- hotspot: (i32,i32) cursor offset from origin
- position: (i32,i32) current render position
- hover: HitTarget under cursor
- snapshot: GameState for undo

### MouseDownContext (Lines 1936-1939)
Button-press tracking:
- target: HitTarget clicked
- position: (i32,i32) mouse-down location
- Enables click vs drag disambiguation

### Selection (Lines 1921-1924)
Two-click move system:
- Waste or Tableau{column,index}
- Alternative to drag-drop

### CardMetrics (Lines 1801-1810)
Responsive layout:
- card_w, card_h, gaps, offsets, margin
- Computed on WM_SIZE, cached
- Scales 0.35x to 4.0x

### CardSlot (Lines 1813-1816)
Hit test cache:
- top: i32, height: i32
- Populated during paint

## 2. Mouse Event Flow

### WM_LBUTTONDOWN (Lines 772-779)
1. lparam_point() extracts (x,y)
2. hit_test() determines target
3. Store MouseDownContext
4. set_focus() for immediate feedback
5. NO action yet (deferred until button-up)

### WM_MOUSEMOVE (Lines 781-815)
**During Drag:**
- Update drag.position (cursor - hotspot)
- hit_test() -> drag.hover
- request_redraw()

**Drag Initiation:**
- Calculate distance from mouse_down.position
- If distance >= 4px: begin_drag()
- Clears mouse_down, creates DragContext
- SetCapture() for mouse tracking

**Pointer Speed:**
- Tracks velocity for victory animations
- Exponential moving average (80% old, 20% new)
- Clamped to 4000 px/s

### WM_LBUTTONUP (Lines 817-843)
**If Drag Active:**
- hit_test() -> drop_target
- finalize_drag() validates and executes
- ReleaseCapture()
- push_undo() only if successful
- force_redraw()

**If No Drag:**
- Verify target unchanged
- handle_click() if same target
- Cancel selection if target changed

## 3. Drag-and-Drop

### begin_drag() (Lines 3059-3122)
**From Tableau:**
1. Validate face-up card
2. Clone game state
3. Calculate card top position
4. Extract stack (validates sequence)
5. Calculate hotspot
6. Create DragContext
7. SetCapture()
8. Cache layout metrics

**From Waste:**
- Always single card
- Removed from waste immediately
- Similar DragContext creation

### finalize_drag() (Lines 3124-3220)
**Tableau→Tableau:**
- Different columns only
- Validates alternating colors, descending ranks
- On success: place, reveal source top, update focus
- On failure: cancel (return cards)

**Tableau→Foundation:**
- Single cards only
- Validates Ace on empty or same suit +1 rank

**Invalid Drop:**
- Returns cards to source
- Restores selection

## 4. Hit Testing

### hit_test() (Lines 2675-2787)
**Order:** Stock → Waste → Foundations → Tableaus → None

**Stock:** Column 0, top row, full card height
**Waste:** Column 1, only if cards present
**Foundations:** Columns 3-6, always clickable
**Tableaus:** Most complex:
1. X-axis filter (column bounds)
2. Empty column: card_index=None
3. Reverse iteration (topmost first)
4. Variable height (visible region only)
5. Fallback for bottom card

**point_in_rect():** Half-open intervals prevent overlap

## 6. Double-Click (Lines 845-893)

### WM_LBUTTONDBLCLK
1. Cancel active drag if present
2. hit_test() current position
3. From Waste: move_waste_to_any_foundation()
4. From Tableau top card: move_tableau_top_to_any_foundation()
5. push_undo() if successful

**Difference from Single-Click:** Automatically finds valid foundation.

## Key Design Patterns

1. **Two-Phase Input:** Button-down stores context, button-up executes action
2. **Threshold Disambiguation:** 4px prevents accidental drags
3. **Snapshot-Before-Modify:** Clone before change, save only on success
4. **Reverse Iteration:** Topmost overlapped cards get priority
5. **Dual Input Modes:** Drag-drop AND two-click selection coexist
6. **Cached Positions:** CardSlots optimize hit testing
7. **Focus Normalization:** All focus changes validated
8. **Accelerator-Based Keyboard:** OS handles shortcuts, not raw keys

---

## Performance

- Early X-axis rejection in tableaus
- Reverse iteration (first match wins)
- Slot caching avoids offset accumulation
- Half-open intervals prevent overlap
- Lazy layout recomputation
- request_redraw() async, force_redraw() immediate
